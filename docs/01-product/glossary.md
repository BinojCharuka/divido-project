# Glossary

**Status:** PROPOSED

| Term | Definition |
|---|---|
| Actual income | Income transaction that the user recorded as received |
| Planned income | Estimate of income for a particular month |
| Expense | Outgoing spending recorded by the user |
| Transaction | A dated income or expense record |
| Income source | Origin of income, such as salary or freelance work |
| Payment method | How the transaction was paid, such as cash or card; not an account balance |
| Category | Label for a transaction, such as groceries or transport |
| Built-in category | Category provided by Divido and managed by the system |
| Custom category | Category created and owned by an individual user |
| Kakeibo group | One of Needs, Wants, Culture, or Unexpected |
| Monthly budget | A user's plan for a particular calendar month |
| Savings target | Amount the user intends to save during a month |
| Actual net savings | Recorded actual income minus recorded expenses for the selected period; not a verified bank balance |
| Remaining budget | Budgeted amount left after matching actual expenses against the applicable budget; not money available in a bank account |
| Spending habit/pattern | Repeated spending pattern detected from the user's recorded transactions; not a guarantee of future spending |
| Soft delete | Marking a record deleted while retaining it for possible restoration |
| Restore | Returning a soft-deleted record to active status |
| User story | A user-centred statement of desired capability |
| Use case | Structured description of actor/system interactions to achieve a goal |
| Acceptance criteria | Testable conditions that determine whether a story is complete |
| API contract | Agreed request/response behaviour between frontend and backend |
| Migration | Versioned database schema/data change managed by Flyway |
| Traceability | Links between requirements, stories, UI, APIs, database changes, and tests |
| Requirements freeze | Explicitly approved baseline whose changes require change control |
